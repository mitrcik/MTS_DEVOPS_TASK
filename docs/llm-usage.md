# Использование LLM

LLM в проекте — **инструмент разработки**, а не часть runtime. Стенд, конвейер, release controller и
все проверки работают без доступа к какому-либо AI-провайдеру, платных подписок и GPU.
Это допустимый уровень интеграции [13:39, 28:28, 34:27].

## Что и как применялось

| Что | Инструмент | Входные данные |
|---|---|---|
| Реализация кода, чартов, Ansible-ролей, workflow и документации | Claude Code (облачная сессия, модель семейства Claude) | мастер-промпт команды `docs/llm/master-prompt.md`, Word «Конкурс кейсов DevOps 2.1», расшифровка ВКС |

Мастер-промпт задаёт требования, разрешённые послабления ВКС с таймкодами, архитектурные границы
(k3d, Helm, blue-green, SOPS+age, Prometheus/Grafana), критерии приёмки и запрет выдавать
непроверенное за проверенное. Ключевые последующие запросы в сессии: «Выполни все задания
согласно мастер-промпту».

## Как проверялся результат LLM

Ни один артефакт не принят «на слово» — каждый проверен инструментом или реальным запуском:

| Часть | Проверка |
|---|---|
| Код API | 26 unit-тестов pytest в образе (`scripts/ci.sh test`), ruff |
| Логика gate | 17 unit-тестов (`scripts/tests/test_gate.py`) |
| Правила алертов | `promtool check rules` и `promtool test rules` (6 тестовых групп) |
| Конфигурации | `helm lint --strict` + JSON-схемы values, `promtool check config`, `amtool check-config`, yamllint, shellcheck |
| Инфраструктура и релизы | реальные прогоны `make up`, `make test-e2e` (15 сценариев) на Ubuntu 24.04 и в GitHub Actions |
| Версии и checksum | загрузка с официальных адресов и сверка sha256 (checksum Helm подтверждён загрузкой с get.helm.sh в GitHub Actions) |

Примеры ошибок, найденных проверками (а не LLM): повторный `make up` перевыпускал начальную версию
(сценарий `idempotent-up`); прерванный `helm upgrade` блокировал следующий релиз (сценарий
прерывания); kubelet ≥ 1.35 не стартует на cgroup v1; неверные ожидания в тестах `promtool`.
Каждая исправлена и перепроверена.

## Экономия времени

**Количественно не оценивалась**: базовый замер (та же работа без LLM) не проводился, поэтому
любая цифра была бы выдумкой. Качественно: генерация шаблонного кода и документации заняла
меньше времени, чем проверка и отладка на реальном стенде, — основная часть работы пришлась на
запуски, диагностику и исправления.

## Ограничения и риски

- LLM может уверенно ошибаться в версиях, флагах CLI и поведении инструментов: поэтому версии
  сверены с реальными релизами, флаги Helm 4 — с `helm upgrade --help` закреплённой версии.
- Команда должна понимать устройство решения: ответы для защиты — `docs/defense-notes.md`.
- В runtime нет зависимостей от внешних API — нечего передавать жюри (ключей не требуется).
