# Использование LLM

LLM в проекте — **инструмент разработки**, а не часть работающей системы (runtime). Стенд,
конвейер, контроллер релизов и все проверки работают без доступа к AI-провайдерам, без платных
подписок и без GPU. На консультации организаторы подтвердили, что такой уровень использования LLM
допустим.

## Что и как применялось

| Что | Инструмент | Входные данные |
|---|---|---|
| Реализация кода, чартов, Ansible-ролей, workflow и документации | Claude Code (облачная сессия, модель семейства Claude) | мастер-промпт команды `docs/llm/master-prompt.md`, документ кейса «Конкурс кейсов DevOps 2.1», расшифровка консультации с организаторами |

Мастер-промпт задаёт:

- требования кейса;
- послабления, которые организаторы разрешили на консультации (с отметками времени в записи);
- архитектурные границы: k3d, Helm, blue-green, SOPS+age, Prometheus/Grafana;
- критерии приёмки;
- запрет выдавать непроверенное за проверенное.

Ключевые последующие запросы в сессии: «Выполни все задания согласно мастер-промпту».

## Как проверялся результат LLM

Ни один артефакт не принят «на слово». Каждый проверен инструментом или реальным запуском:

| Часть | Проверка |
|---|---|
| Код API | 26 unit-тестов pytest в образе (`scripts/ci.sh test`), ruff |
| Логика gate (автоматической проверки релиза по метрикам) | 17 unit-тестов (`scripts/tests/test_gate.py`) |
| Правила алертов | `promtool check rules` и `promtool test rules` (6 тестовых групп) |
| Конфигурации | `helm lint --strict` и JSON-схемы values, `promtool check config`, `amtool check-config`, yamllint, shellcheck |
| Инфраструктура и релизы | Реальные прогоны `make up` и `make test-e2e` (15 сценариев) на Ubuntu 24.04 и в GitHub Actions |
| Версии и checksum | Загрузка с официальных адресов и сверка sha256. Checksum Helm подтверждён загрузкой с get.helm.sh в GitHub Actions |

Примеры ошибок, которые нашли проверки, а не LLM:

- повторный `make up` заново выпускал начальную версию (сценарий `idempotent-up`);
- прерванный `helm upgrade` блокировал следующий релиз (сценарий `interrupted`);
- kubelet ≥ 1.35 не стартует на cgroup v1;
- в тестах `promtool` были неверные ожидания.

Каждая ошибка исправлена и перепроверена.

## Экономия времени

**Количественно не оценивалась.** Базовый замер (та же работа без LLM) не проводился, поэтому
любая цифра была бы выдумкой. Качественная оценка: генерация шаблонного кода и документации заняла
меньше времени, чем проверка и отладка на реальном стенде. Основная часть работы пришлась на
запуски, диагностику и исправления.

## Ограничения и риски

- LLM может уверенно ошибаться в версиях, флагах CLI и поведении инструментов. Поэтому версии
  сверены с реальными релизами, а флаги Helm 4 — с `helm upgrade --help` закреплённой версии.
- Команда должна понимать устройство решения. Ответы для защиты — в `docs/defense-notes.md`.
- В runtime нет зависимостей от внешних API, поэтому жюри не нужны никакие ключи.
